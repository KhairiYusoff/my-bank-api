# US-6005 — Admin Dashboard — Summary Stats & Quick Access

**Phase:** 6 (addendum)
**Repos:** `my-bank-api`, `my-bank-admin-portal`
**Epic:** Admin Detail Pages
**Status:** 🟡 Ready for Development
**Depends on:** US-6001, US-6002, US-6003 (detail pages must exist for quick-link navigation)

---

## Value Statement

As an admin or banker, I want to land on a dashboard that shows live summary stats and quick access to key areas, so I can immediately understand the state of the system and get to the right place without hunting through the sidebar.

---

## Background

The current dashboard is a stub — it shows "Welcome, Admin!" and a logout button. There is nothing actionable on it. An admin logging in has no immediate signal of what needs attention.

The API already has all the data needed — customers, accounts, and transactions endpoints are live. This story adds a `/admin/dashboard` BE endpoint that returns aggregated counts and recent records, and replaces the stub with a real layout.

## Acceptance Criteria

### BE-1: Dashboard Endpoint

1. `GET /admin/dashboard` added to a new `dashboard.routes.js`
2. Allowed roles: `admin`, `banker`
3. Returns:
   ```json
   {
     "success": true,
     "data": {
       "counts": {
         "customers": 1204,
         "accounts": 987,
         "staff": 12,
         "transactionsToday": 3421
       },
       "pendingApplications": [
         {
           "_id": "...",
           "name": "Ali Hassan",
           "email": "ali@email.com",
           "createdAt": "..."
         }
       ]
     }
   }
   ```
4. `counts` fetched via `Promise.all` — parallel queries, not sequential
5. `transactionsToday` counts transactions where `createdAt >= start of today (UTC)`
6. `pendingApplications` — customers where `applicationStatus === "Pending"`, sorted by `createdAt desc`, limit 5, returns `_id`, `name`, `email`, `createdAt` only
7. Activity logged: `activityLogger("VIEW_DASHBOARD", "Staff viewed dashboard")`
8. Route → Controller → Service pattern

### BE-2: Service Method

1. `getDashboardSummary()` added to a new `dashboard.service.js`
2. Uses `Promise.all([...])` for all 4 count queries

### FE-1: RTK Query — New Slice

1. New file: `src/features/dashboard/store/dashboardApi.ts`
2. `getDashboardSummary` query — `GET /admin/dashboard`
3. `providesTags: ["Dashboard"]`
4. `keepUnusedDataFor: 60` (1 minute cache — stats are near-real-time, not live)
5. Export `useGetDashboardSummaryQuery`

### FE-2: Dashboard Types

1. New file: `src/features/dashboard/types/index.ts`
2. Types: `DashboardCounts`, `PendingApplication`, `DashboardSummary`

### FE-3: Replace Dashboard Stub

1. Replace `Dashboard.tsx` stub with full layout
2. Header: "Welcome back, {name}." + current date (right-aligned)
3. Stat cards row — 4 cards: Customers, Accounts, Staff, Transactions Today
   - Each card: label, count (Typography variant="h4"), "View All" Button that navigates to the relevant list page
   - Loading state: show `—` in place of count
4. Pending Applications section (visible to both admin and banker):
   - Table with columns: Name, Email, Applied (formatted date), Action
   - "View" button on each row navigates to `/users/:id` with `state: { user: application }`
   - Empty state: `Alert severity="info"` — "No pending applications."
5. Remove `LogoutButton` from dashboard — it already exists in the sidebar/header

### FE-4: Register dashboardApi in store

1. Add `dashboardApi.reducer` and `dashboardApi.middleware` to `src/app/store/index.ts`
