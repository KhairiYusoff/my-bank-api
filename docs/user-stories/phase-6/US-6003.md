# US-6003 — Admin Views Account Detail Page

**Phase:** 6
**Repos:** `my-bank-api`, `my-bank-admin-portal`
**Epic:** Admin Detail Pages
**Status:** 🟡 Ready for Development
**Depends on:** US-6001 (shares `ProfileSection` component — build US-6001 first)

---

## Value Statement

As an admin or banker, I want to click on any account in the accounts list and see its full detail — balance, type, status, linked holder, and key audit fields — so I can investigate account issues with full context rather than reading a single table row.

---

## Background

The accounts list at `/accounts` currently has a "View Details" stub button wired to nothing. There is no `GET /admin/accounts/:accountNumber` endpoint and no detail page. Admins who need to investigate an account must cross-reference the accounts table, the transactions table, and the users table manually.

The Account model has all core fields (`balance`, `status`, `accountType`, `branch`, `currency`, `dateOpened`, `dateClosed`, `overdraftLimit`, `minimumBalance`, `interestRate`) but is missing attribution fields (`createdBy`, `statusChangedBy`, `closedBy`). This story builds the endpoint and detail page using what currently exists. Attribution gaps are tracked as model debt below and will be addressed before Phase 7.

## Model Debt (do NOT block this story — address before Phase 7)

| Missing field | Purpose |
|---|---|
| `timestamps: true` | `createdAt` / `updatedAt` on Account document |
| `createdBy` (ref User) | Which banker or system opened the account |
| `statusChangedBy` (ref User) | Who set the account to Dormant/Closed |
| `statusChangedAt` (Date) | When the last status change occurred |
| `closedBy` (ref User) | Who formally closed the account |

## Acceptance Criteria

### BE-0: ActivityLog Enum Prerequisite ✅ Done Jun 1 2026

`"VIEW_CUSTOMER_PROFILE"`, `"VIEW_STAFF_PROFILE"`, `"VIEW_ACCOUNT_DETAIL"`, `"ACCOUNT_STATUS_CHANGED"` added to `ActivityLog.js` enum. This unblocks all Phase 6 stories.

### BE-1: Fetch Endpoint

1. `GET /admin/accounts/:accountNumber` added to `account.routes.js`
2. Allowed roles: `admin`, `banker`
3. Returns full Account document with `user` populated — `name`, `email`, `phoneNumber`, `role` only (no `password`, no `refreshToken`)
4. Returns `404` `{ success: false, message: "Account not found" }` if not found
5. Response: `{ success: true, message: "Account fetched", data: { ...account } }`
6. Activity logged: `activityLogger("VIEW_ACCOUNT_DETAIL", "Staff viewed account detail")`
7. Route → Controller → Service pattern

### BE-2: Service Method

1. `getAccountByNumber(accountNumber)` added to `account.service.js`
2. `Account.findOne({ accountNumber }).populate("user", "name email phoneNumber role")`
3. Throws `404` if not found

### BE-3: Status Update Endpoint

1. `PATCH /admin/accounts/:accountNumber/status` added to `account.routes.js`
2. Allowed roles: `admin`, `banker`
3. Validates `status` is one of `["Active", "Dormant", "Closed"]`
4. `Closed` is terminal — reject request if current status is already `Closed`
5. Transitioning to `Closed` sets `dateClosed: Date.now()`
6. Returns updated account document
7. Activity logged: `activityLogger("ACCOUNT_STATUS_CHANGED", \`Account \${accountNumber} status changed to \${status}\`)`

### FE-1: List Page — Wire Up Button

1. In `AccountsList.tsx`, replace `Tooltip + IconButton + VisibilityIcon` with `Button variant="text" size="small" startIcon={<VisibilityIcon />}` that calls `navigate("/accounts/" + account.accountNumber)`
2. Import `useNavigate` from `react-router-dom`
3. No other changes to the list

### FE-2: Routing

1. New route in `routes.tsx`: `/accounts/:accountNumber` → `AccountDetailPage`, `requiresAuth: true`
2. On navigation from list: account object passed as `state: { account }`
3. On direct URL / refresh: calls `GET /admin/accounts/:accountNumber` to hydrate

### FE-3: RTK Query Endpoints

1. `getAccountByNumber` query added to `accountsApi.ts`:
   - `GET /admin/accounts/:accountNumber`
   - `providesTags: [{ type: "Account", id: accountNumber }]`
2. `updateAccountStatus` mutation added to `accountsApi.ts`:
   - `PATCH /admin/accounts/:accountNumber/status`
   - `invalidatesTags: ["Account"]`
3. Both hooks exported: `useGetAccountByNumberQuery`, `useUpdateAccountStatusMutation`

### FE-4: Detail Page Layout

1. New file: `src/features/accounts/pages/AccountDetailPage.tsx`
2. Header: account number (h5), `StatusChip` for account status, account type label (plain text)
3. Header action buttons:
   - `Manage Status` — opens `ChangeStatusModal` (reused from US-6001, no modifications needed)
   - `View Transactions` — navigates to `/transactions?account=<accountNumber>`
4. Back link: `← Back to Accounts` navigates to `/accounts`
5. Sections via shared `ProfileSection` component (built in US-6001):
   - **Account Info**: Account Number, Account Type, Status, Currency, Branch, Date Opened, Date Closed
   - **Financials**: Current Balance (`formatCurrency`), Minimum Balance (`formatCurrency`), Overdraft Limit, Interest Rate
   - **Account Holder**: Name, Email, Phone, Role + `View Full Profile →` link to `/users/:userId`
6. `null` / `undefined` values render as `—` (em dash), never as `"null"` or `"undefined"`
7. Balance values use `formatCurrency()` from `@/utils/formatters`

### FE-5: Loading & Error States

1. Loading (direct URL / refresh): `CircularProgress` centred on page
2. API error: `Alert severity="error"` with message
3. 404: `Alert severity="warning"` with "Account not found" and back link to `/accounts`
