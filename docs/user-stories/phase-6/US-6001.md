# US-6001 — Admin Views Full Customer Profile (Detail Page)

**Phase:** 6
**Repos:** `my-bank-api`, `my-bank-admin-portal`
**Epic:** Admin Detail Pages
**Status:** 🟡 Ready for Development
**Depends on:** Phase 5 complete

---

## Value Statement

As an admin or banker, I want to click on any customer in the users list and see their complete profile — personal info, KYC data, employment, address, next of kin, and account status — so I can investigate issues, verify identity, and take action (change status, delete) without guessing from a truncated table row.

---

## Background

Currently the Users list table shows 7 columns and dumps all actions inline. There is no `GET /admin/customer/:id` endpoint, so viewing full profile data requires querying MongoDB directly. The list already returns the full document from `GET /users/customers`, but:

1. Not all fields fit in a table
2. There is no dedicated view for a single customer's complete record
3. Status changes happen inline (fixed in Phase 3 hotfix) — they should happen in context of the full profile

The detail page is read from list-page data passed via router state on navigation, and re-fetched by `_id` if the user lands directly on the URL (e.g. refresh). This requires a new backend endpoint.

## Acceptance Criteria

### BE-1: New API Endpoint

1. `GET /admin/customer/:customerId` added to `admin.routes.js`
2. Allowed roles: `admin`, `banker`
3. Returns the full User document for the given `_id`, excluding `password` and `refreshToken`
4. Returns `404` with `{ success: false, message: "Customer not found" }` if ID does not exist or user role is not `customer`
5. Response follows the existing `success()` utility format: `{ success: true, message: "Customer fetched", data: { ...user } }`
6. Activity logged via `activityLogger("VIEW_CUSTOMER_PROFILE", "Staff viewed customer profile")`
7. Implementation follows Route → Controller → Service pattern — business logic in `admin.service.js`

### BE-2: Service Method

1. New `getCustomerById(customerId)` method in `admin.service.js`
2. Uses `User.findOne({ _id: customerId, role: "customer" }).select("-password -refreshToken")`
3. Throws `404` if not found

### FE-1: List Page — Actions Simplified

1. `Manage` button removed from the Actions cell in `UsersList.tsx`
2. `Activity` button removed from the Actions cell in `UsersList.tsx`
3. `Delete` icon button removed from the Actions cell — Delete moves to the detail page
4. `[View →]` button added — navigates to `/users/:id` via React Router `useNavigate`
5. Actions column is now a single button — adjust column width accordingly

### FE-2: Routing

1. New route registered in `routes.tsx`: `/users/:id` → `UserDetailPage`
2. Route is auth-protected (`requiresAuth: true`)
3. On navigation from the list, user object is passed as router state (`state: { user }`) to avoid an extra API call on first load
4. On direct URL access or page refresh, the page calls `GET /admin/customer/:id` to hydrate

### FE-3: New RTK Query Endpoint

1. `getCustomerById` query added to `usersApi.ts`:
   - `GET /admin/customer/:id`
   - `providesTags: [{ type: "User", id }]`
2. `useGetCustomerByIdQuery` hook exported

### FE-4: Detail Page — Layout

1. New file: `src/features/users/pages/UserDetailPage.tsx`
2. Page header: customer name (h5), two `StatusChip` components (account status + application status), role label
3. Header action buttons: `Manage Status` (opens `ChangeStatusModal`) and `Delete` (opens `ConfirmationDialog`)
4. Back link: `← Back to Users` navigates to `/users`
5. Content split into labelled sections using a shared `DetailSection` component (see FE-5)
6. Sections: Account Info, Personal Info, Employment, Address, Next of Kin, Preferences
7. Sections where all fields are `null` / `undefined` show a `—` placeholder row, not an error
8. `View Full Activity Log` button at the bottom opens `UserActivityModal` (already exists)

### FE-5: Shared `DetailSection` Component

1. New file: `src/components/shared/DetailSection.tsx`
2. Props: `title: string`, `rows: Array<{ label: string; value: React.ReactNode }>`
3. Renders a titled card with a two-column label/value grid (label left, value right)
4. Used by `UserDetailPage`, `StaffDetailPage` (US-6002), and `AccountDetailPage` (US-6003) — must not contain any domain-specific logic
5. Empty/null values render as `—` (em dash), never as `"null"` or `"undefined"`

### FE-6: Loading & Error States

1. While fetching (direct URL access): show `CircularProgress` centred on page
2. On API error: show `Alert severity="error"` with message
3. If customer not found (404): show `Alert severity="warning"` with "Customer not found" and back link

## Out of Scope

- Editing customer profile fields from this page (admin cannot edit customer KYC data)
- Showing the customer's linked bank accounts on this page (separate feature, Phase 7+)
- Pagination or filtering on the detail page
- Any changes to `GET /users/customers` (list endpoint) — unchanged
