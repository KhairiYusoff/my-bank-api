# US-8002: Staff First-Login Flow (Security Handshake)

**Status:** ✅ Completed
**Phase:** 8 — Role Expansion
**Repo:** `my-bank-api`, `my-bank-admin-portal`

---

## 1. Problem Statement
When an admin creates a new staff member (Banker or Auditor), the staff member is assigned a temporary password. To ensure system security and personal accountability, staff members must be forced to change this temporary password upon their first login. Access to banking operations must be blocked until this security handshake is completed.

## 2. User Story
As a **New Staff Member**,  
I want **to be forced to change my temporary password on my first login**,  
So that **my account is secured with a private credential before I begin my duties.**

## 3. Acceptance Criteria

### BE — First Login Detection & Enforcement
- [x] Utilize the existing `isFirstTime` flag in the `User` model to detect if a user is logging in for the first time.
- [x] If `isFirstTime` is `true`, any API request to restricted routes (except for password change) should return a specific status or hint (e.g., `403 Forbidden` with a "First login change required" message).
- [x] The `auth/login` response should include a `mustChangePassword: true` flag if `isFirstTime` is `true`.

### BE — Password Change & Flag Update
- [x] Update the password change logic to set `isFirstTime = false` upon the first successful password change.
- [x] Ensure `passwordChangedAt` is updated (handled by the model's `pre-save` hook).

### FE — Forced Redirect & UI
- [x] When the login response contains `mustChangePassword: true`, the user must be redirected to a dedicated "Secure Your Account" page.
- [x] Prevent the user from navigating to the dashboard or other admin features until the password has been changed.
- [x] Provide a clear form for the **Security Handshake**:
    1. Current (temporary) Password.
    2. New Password.
    3. Confirm New Password.

### FE — Navigation Guard
- [x] Implement a route guard or global check that redirects staff with `isFirstTime: true` back to the security handshake page if they try to access other portal routes.

- [x] They cannot access any other part of the portal without changing their password.
- [x] After changing the password, `isFirstTime` is set to `false`, and they are redirected to the dashboard.
