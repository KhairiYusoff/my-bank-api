# US-8001: Add Auditor Role

**Status:** ✅ Done
**Phase:** 8 — Role Expansion
**Repo:** `my-bank-api`

---

## 1. Problem Statement
To ensure better security, fraud detection, and regulatory compliance, the system requires a dedicated read-only role for internal auditors. Currently, bankers and admins have broad mutation powers, making it difficult to maintain a strict separation of duties during investigations. An auditor needs to see everything (including unmasked sensitive data) without the ability to change anything.

## 2. User Story
As an **Internal Auditor**,  
I want **read-only access to all banking data, unmasked transaction details, and full system activity logs**,  
So that **I can conduct thorough investigations and audits without any risk of accidentally or intentionally altering data.**

## 3. Acceptance Criteria

### BE — User Model & Role Definition
- [x] Add `auditor` to the `role` enum in the `User` model.
- [x] Add `auditor` to the roles constant (if applicable/exists in `src/shared/constants/roles.js`).

### BE — Authorization (RBAC)
- [x] Update `authorizeRoles()` calls across all routes to include `auditor` for read-only endpoints (GET requests).
- [x] Ensure `auditor` is **excluded** from all mutation endpoints (POST, PUT, PATCH, DELETE), returning `403 Forbidden` if attempted.
- [x] Specifically grant `auditor` access to:

    - [x] `GET /accounts/all` and `GET /accounts/:accountNumber/detail`

    - [x] `GET /audit/all` (Full system activity logs)
    - [x] `GET /onboarding/pending` (Read-only view of applications)

### BE — Transaction Masking
- [x] Ensure the transaction detail service/controller logic honors the `auditor` role to return unmasked data (similar to `admin`).
