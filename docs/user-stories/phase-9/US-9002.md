# US-9002 — FD Onboarding UI & Approval Hub

**Phase:** 9
**Repos:** `my-bank-customer`, `my-bank-admin-portal`
**Status:** ⬜ Planned
**Depends on:** US-9001 (Unified Provisioning Engine)

---

## Value Statement

As a **Customer**, I want a self-service UI to request new account types (FD/Current/Business), and as a **Banker**, I want a centralized "Approval Hub" in the Admin Portal to review and approve these account requests, so that account provisioning is a structured, audited, and role-based workflow.

---

## Background

With the backend unified provisioning engine (US-9001) in place, we need frontend components to interact with this new request/approval workflow.

1. **Customer Portal:** Needs a way to initiate requests for products other than the default Savings account.
2. **Admin Portal:** Needs a single view (the Approval Hub) to monitor and approve these pending requests, replacing the fragmented notification or manual processes.

---

## Acceptance Criteria

### FE-1: Customer Product Request

- [ ] Add "Open New Product" section to Customer Dashboard.
- [ ] Create interactive request form supporting:
    - Account Type Selection (Current, Business, FD).
    - FD-specific configuration (Principal, Lock Period selection).
    - Business-specific document attachment (Mock input field).
- [ ] Submit button triggers `POST /accounts/request` and handles loading/error states.

### FE-2: Banker Approval Hub (Tabbed Interface)

- [ ] Implement `ApprovalHub` layout with tabs:
    - **Tab 1: Pending Onboarding** (existing onboarding applications).
    - **Tab 2: Account Requests** (new product requests from US-9001).
- [ ] Create listing table for pending accounts (`status: pending_approval`) in Tab 2.
- [ ] Implement approval/rejection actions.

---

## Technical Tasks

1. **Customer:** Implement "Open New Product" UI and `POST /accounts/request` integration in `my-bank-customer`.
2. **Admin:** Build `ApprovalHub` in `my-bank-admin-portal`:
   - Layout with tabs.
   - Request listing component (`GET /admin/account-requests`).
   - Approval action component (`POST /admin/account-requests/:id/approve`).
