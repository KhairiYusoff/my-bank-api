# US-9001 — Unified Provisioning Engine

**Phase:** 9
**Repos:** `my-bank-api`
**Status:** ⬜ Planned
**Depends on:** Phase 8 completion

---

## Value Statement

As the `AccountService`, I want a unified, product-aware `provisionAccount()` engine that enforces product-specific rules (min balance, lock period, KYC level) so that we eliminate inconsistent account creation logic and ensure that high-risk/complex products like Fixed Deposits (FDs) cannot be provisioned without all required business data.

---

## Background

Currently, the `onboarding` module has logic to auto-create a `Savings` account. This is now deprecated in favor of a progressive disclosure model. Product-specific provisioning (Current, Business, FD) currently lacks:
1. Product-specific validation (min balance, FD lock parameters).
2. Approval workflow (Current/Business/FD require Banker review).
3. Immutable product metadata (maturity date, principal, interest rate).

This story centralizes all provisioning into a single atomic service.

---

## Acceptance Criteria

### BE-1: Account Request (`POST /accounts/request`)

| Check | Rule | Error message | HTTP |
|---|---|---|---|
| 1 | `amount < MIN_BALANCE[type]` | "Initial deposit amount below minimum for {type}" | 400 |
| 2 | `type === 'fixed_deposit'` | Require `lockPeriod` (1/3/6/12) + `linkedAccount` ID | 400 |
| 3 | `type === 'business'` | Require `companyRegistrationDoc` (mocked as string link) | 400 |
| 4 | `linkedAccount` exists | Must belong to requester, status: `active` | 404/403 |

**Resulting State:** Account record created with status: `pending_approval`.

### BE-2: Approval Workflow (`POST /admin/account-requests/:id/approve`)

1. Validates **Banker** session.
2. Updates `AccountRequest` status to `approved`.
3. Provisions the actual `Account` document:
   - Sets `status: active`.
   - Copies metadata from `AccountRequest`.
   - If FD: calculates `maturityDate`, sets `interestRate` based on `lockPeriod`.
4. Records action in `ActivityLog`.

## Technical Tasks

1. **Model/Schema:** Add `pending_approval` status to `Account` schema.
2. **Service:** Update `AccountService.js`:
   - `requestAccount(userId, data)`: Creates `Account` doc with `status: pending_approval`.
   - `approveAccount(accountId)`: Updates `Account` doc status to `active` (Restricted to `banker` role).
3. **Controller:** Add endpoints to `account.routes.js`:
   - `POST /accounts/request`
   - `GET /admin/account-requests` (Restricted to `banker`)
   - `POST /admin/account-requests/:id/approve` (Restricted to `banker`)
