# US-7003 — Banker Sets Overdraft Limit on Current/Business Account

**Phase:** 7
**Repos:** `my-bank-api`, `my-bank-admin-portal`
**Epic:** Account Type Differentiation
**Status:** ✅ Completed
**Depends on:** US-7001 (Account model enum fix must be in place — overdraft only applies to `current` and `business`)

---

## Value Statement

As a banker or admin, I want to set an overdraft limit on a Current or Business account so that eligible customers can make transfers and withdrawals beyond their available balance up to that limit.

---

## Background

The `overdraftLimit` field already exists on the Account model and is returned in `GET /accounts/:accountNumber/detail`. However, there is no way to update it — no endpoint and no UI. The field is currently display-only on the Account Detail page in the admin portal.

The business rule: only `current` and `business` account types are eligible for overdraft. Savings and Fixed Deposit accounts must be blocked. Default is `0`.

## Acceptance Criteria

### BE-1: New Endpoint

1. `PATCH /accounts/:accountNumber/overdraft-limit` added to `account.routes.js`
2. Allowed roles: `admin`, `banker`
3. Activity logged: `activityLogger("UPDATE_OVERDRAFT_LIMIT", "Staff updated overdraft limit")`
4. Request body: `{ overdraftLimit: number }`
5. Validation (in route, using `express-validator`):
   - `overdraftLimit` must be present, numeric, and `>= 0`
   - Returns 400 with validation error array if invalid
6. Response on success:
   ```json
   { "success": true, "message": "Overdraft limit updated", "data": { "accountNumber": "MYB...", "overdraftLimit": 5000 } }
   ```
7. Error cases:
   - Account not found → 404
   - Account type is `savings` or `fixed_deposit` → 400 `"Overdraft is not available for this account type"`

### BE-2: Service Method in `account.service.js`

1. New method: `setOverdraftLimit(accountNumber, overdraftLimit)`
2. Finds account by `accountNumber`
3. Throws 404 if not found
4. Throws 400 if `account.accountType` is `savings` or `fixed_deposit`
5. Sets `account.overdraftLimit = overdraftLimit` and calls `account.save()`
6. Returns `{ accountNumber: account.accountNumber, overdraftLimit: account.overdraftLimit }`

### BE-3: Controller in `account.controller.js`

1. New export: `setOverdraftLimit`
2. Calls `accountService.setOverdraftLimit(accountNumber, overdraftLimit)` from `req.params` and `req.body`
3. Returns `res.status(200).json(success("Overdraft limit updated", result))`
4. Controller handles thrown errors via the existing try/catch pattern

### FE-1: New RTK Query Mutation in `accountsApi.ts`

1. New mutation: `setOverdraftLimit`
   ```ts
   setOverdraftLimit: builder.mutation<
     { success: boolean; message: string; data: { accountNumber: string; overdraftLimit: number } },
     { accountNumber: string; overdraftLimit: number }
   >({
     query: ({ accountNumber, overdraftLimit }) => ({
       url: `/accounts/${accountNumber}/overdraft-limit`,
       method: "PATCH",
       body: { overdraftLimit },
     }),
     invalidatesTags: (_result, _error, { accountNumber }) => [
       { type: "Account", id: accountNumber },
       "Account",
     ],
   })
   ```
2. `useSetOverdraftLimitMutation` hook exported alongside existing hooks

### FE-2: `SetOverdraftLimitDialog` Component

1. New file: `src/features/accounts/components/SetOverdraftLimitDialog.tsx`
2. Props: `open: boolean`, `onClose: () => void`, `account: Account`
3. Contains:
   - MUI `Dialog` with title "Set Overdraft Limit"
   - Subtitle showing `account.accountNumber`
   - Number input field labelled "Overdraft Limit (RM)", min `0`, step `0.01`
   - Controlled state: `value` initialised from `account.overdraftLimit ?? 0`
   - `Cancel` button: calls `onClose()`
   - `Save Limit` button: disabled while loading; calls `setOverdraftLimit` mutation
4. On success: calls `onClose()`, parent page shows snackbar "Overdraft limit updated"
5. On error: shows inline error message below the input using MUI `FormHelperText`
6. Client-side validation: value must be `>= 0`; shows "Must be 0 or greater" if negative

### FE-3: `AccountDetailPage.tsx` Updates

1. Import and render `SetOverdraftLimitDialog`
2. Add `overdraftModalOpen` boolean state (default `false`)
3. In the Account Info section row for "Overdraft Limit":
   - Show `[Set Limit]` button (`variant="outlined"` size `"small"`) **only when**:
     - `account.accountType === "current"` OR `account.accountType === "business"`
     - AND `currentUserRole === "admin"` OR `currentUserRole === "banker"`
   - Button `onClick` sets `overdraftModalOpen = true`
4. Render `<SetOverdraftLimitDialog>` at the bottom of the component (after the existing `ChangeStatusModal`)

### FE-4: Types Update in `accounts/types.ts`

- `overdraftLimit` already exists as `number` on the `Account` interface — no type change needed
- Add `SetOverdraftLimitRequest` and `SetOverdraftLimitResponse` types if needed inline in `accountsApi.ts` — no separate type file needed (single use)
