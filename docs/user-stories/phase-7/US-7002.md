# US-7002 — Savings Monthly Withdrawal Cap Enforced

**Phase:** 7
**Repos:** `my-bank-api`
**Epic:** Account Type Differentiation
**Status:** 🟡 Ready for Development
**Depends on:** US-7001 (Account model enum must be correct before accountType === "savings" check is reliable)

---

## Value Statement

As a system, I want to reject a Savings account withdrawal when the customer has already made 4 withdrawals in the current calendar month, so that the Savings account product rule is enforced — preventing customers from using a Savings account as a free unlimited withdrawal account.

---

## Background

The business rule is: **Savings accounts are limited to 4 withdrawals per calendar month.** The 5th attempt in the same month must be rejected with a clear, informative error message.

Currently `withdraw()` has no monthly count check. The cap count is derived dynamically from the Transaction collection — no counter field is needed on the Account model.

---

## Acceptance Criteria

### BE-1: Monthly Cap Check in `withdraw()` (`account.service.js`)

1. The cap check runs **before** the Mongoose session opens (fail fast if already at limit)
2. Only applies when `account.accountType === "savings"`
3. Query counts completed withdrawals for this account in the current calendar month:
   ```js
   const now = new Date();
   const startOfMonth = new Date(now.getFullYear(), now.getMonth(), 1, 0, 0, 0, 0);
   const endOfMonth   = new Date(now.getFullYear(), now.getMonth() + 1, 0, 23, 59, 59, 999);
   const withdrawalCount = await Transaction.countDocuments({
     account: account._id,
     type: "withdrawal",
     createdAt: { $gte: startOfMonth, $lte: endOfMonth },
   });
   ```
4. If `withdrawalCount >= 4`:
   - Throw a 400 error: `"Savings accounts are limited to 4 withdrawals per calendar month. You have used all 4 this month."`
5. Placement: the check runs **after** the account is fetched and validated as Active, but **before** the session opens

### BE-2: Error Shape

The error must follow the existing error pattern in `account.service.js`:
```js
const err = new Error("Savings accounts are limited to 4 withdrawals per calendar month. You have used all 4 this month.");
err.statusCode = 400;
throw err;
```
The controller already catches this and returns `{ success: false, message: err.message }` with the correct status code — no controller changes needed.

### BE-3: No Model Changes

- No `withdrawalCount` field added to `Account.js` — count is queried from transactions
- No counter reset logic — querying by `createdAt` range handles month boundary automatically

---

## Out of Scope

- Proactive warning when approaching the limit (e.g. "You have 1 withdrawal left this month") — not in Phase 7
- Current and Business accounts — no monthly cap applies to them
- FD accounts — blocked entirely at withdrawal (US-7001)
