# US-7008 — Customer Notified When Balance Falls Below Maintenance Threshold

**Phase:** 7
**Repos:** `my-bank-api`, `notification-service`
**Epic:** Account Type Differentiation
**Status:** ✅ Completed
**Depends on:** US-7001 (account type enum must be correct so threshold lookup works)

---

## Value Statement

As a customer, I want to receive a notification when my account balance drops below the maintenance fee threshold, so that I can top up my balance before the next maintenance fee cycle and avoid the charge.

---

## Background

The maintenance fee threshold per account type (from `business-rules.md`):

| Account Type | Threshold |
|---|---|
| `savings` | RM 1,000 |
| `current` | RM 2,000 |
| `business` | RM 5,000 |
| `fixed_deposit` | N/A — no fee |

This notification is **not** sent every time the balance is below threshold — only when the balance **crosses the threshold downward** during a transaction. This avoids spamming customers who are persistently below threshold.

Trigger points:
1. After a `withdrawal` that results in `balanceAfter < threshold`
2. After a `transfer` (debit leg) that results in `fromBalanceAfter < threshold`
3. After a `maintenance fee deduction` in US-7006 cron that results in `balanceAfter < threshold`

The notification is best-effort — failure to send must never cause the transaction itself to fail.

## Acceptance Criteria

### BE-1: Shared Utility — `maintenanceThreshold.js`

1. New file: `src/shared/utils/maintenanceThreshold.js`
2. Exports two functions:

```js
const MAINTENANCE_THRESHOLDS = {
  savings:  1000,
  current:  2000,
  business: 5000,
};

/**
 * Returns the maintenance fee threshold for an account type.
 * Returns null for fixed_deposit and any unknown types.
 */
function getMaintenanceThreshold(accountType) {
  return MAINTENANCE_THRESHOLDS[accountType] ?? null;
}

/**
 * Returns true if the balance is below the maintenance threshold for the given account type.
 * Returns false for fixed_deposit (no threshold applies).
 */
function isBelowMaintenanceThreshold(accountType, balance) {
  const threshold = getMaintenanceThreshold(accountType);
  if (threshold === null) return false;
  return balance < threshold;
}

module.exports = { getMaintenanceThreshold, isBelowMaintenanceThreshold };
```

### BE-2: Shared Notification Helper — `notifyBelowThreshold`

1. In `src/shared/utils/maintenanceThreshold.js`, export a third function:

```js
const { sendNotification } = require("../services/notification.service");

async function notifyBelowThreshold(account) {
  const threshold = getMaintenanceThreshold(account.accountType);
  if (threshold === null) return; // FD or unknown — skip
  if (account.balance >= threshold) return; // above threshold — skip

  try {
    await sendNotification({
      type: "balance_warning",
      title: "Low Balance Alert",
      message: `Your ${account.accountType} account (${account.accountNumber}) balance is RM ${account.balance.toFixed(2)}, which is below the RM ${threshold.toLocaleString()} minimum. A monthly maintenance fee may apply.`,
      link: `/accounts/${account.accountNumber}`,
      recipient: { role: "customer", userId: account.user.toString() },
      source: { service: "my-bank-api", id: account._id.toString() },
      data: {
        accountNumber: account.accountNumber,
        balance: account.balance,
        threshold,
      },
      read: false,
      delivered: false,
    });
  } catch (err) {
    // Best-effort — never block the calling operation
    console.error("[Notify] Failed to send low balance alert:", err.message);
  }
}

module.exports = { getMaintenanceThreshold, isBelowMaintenanceThreshold, notifyBelowThreshold };
```

### BE-3: Trigger in `account.service.js` — `withdraw()`

After `session.commitTransaction()` and before the existing withdrawal notification:
```js
await notifyBelowThreshold(account);
```
- `account` at this point has the updated `balance` (after deduction)
- This call is fire-and-forget — any error is caught inside `notifyBelowThreshold`

### BE-4: Trigger in `transaction.service.js` — `transferFunds()`

After `session.commitTransaction()`, in the post-commit notification block:
```js
await notifyBelowThreshold(fromAccount);
```
- `fromAccount.balance` at this point is `fromBalanceAfter` (post-debit)
- Only check `fromAccount` — the recipient getting credited cannot fall below threshold from a transfer credit

### BE-5: Trigger in `maintenanceFee.cron.js` (US-7006)

After each fee deduction, before the fee notification:
```js
await notifyBelowThreshold(account);
```
- `notifyBelowThreshold` is idempotent (just checks current state) so calling it alongside the fee notification is safe

### BE-6: notification-service — No Changes Required

The notification-service already accepts `type: "balance_warning"` as a free-form string in the Notification model. No schema changes required in `notification-service`.

## Out of Scope

- Deduplication of notifications (e.g. do not re-notify if already notified within the same month) — not in Phase 7
- Email notification for low balance — in-app notification only
- Admin/banker visibility of low-balance accounts — Phase 10 (attention signals on dashboard)
