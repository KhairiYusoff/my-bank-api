# US-7005 — Customer Sees Account Type Rules and Limits in Portal

**Phase:** 7
**Repos:** `my-bank-customer`
**Epic:** Account Type Differentiation
**Status:** 🟡 Ready for Development
**Depends on:** US-7001 (account type enum must be lowercase in DB before this renders correctly)

---

## Value Statement

As a customer, I want to see the rules and limits that apply to each of my accounts — daily transfer cap, max single transfer, monthly withdrawal allowance, and overdraft limit — so I am not surprised when a transaction is rejected and I understand what my account can do.

---

## Background

After US-7001 enforces account type rules server-side, customers will start receiving error messages like "Transfer amount exceeds the RM5,000 single transfer limit". Without any UI that surfaces these limits in advance, this is a bad experience. The customer needs to see the applicable rules before they attempt a transaction.

The `AccountDetailsPage` currently shows balance and transaction history. The full `Account` object (with `accountType`, `overdraftLimit`) is available from `GET /accounts` (list endpoint) which is already called on the accounts list page.

## Acceptance Criteria

### FE-1: Account Limits Utility

1. New file: `src/features/accounts/utils/accountLimits.ts`
2. Exports a constant `ACCOUNT_LIMITS` and a helper `getAccountLimits(accountType: string)`:
   ```ts
   const ACCOUNT_LIMITS: Record<string, AccountLimits> = {
     savings:        { dailyLimit: 10000,  maxSingle: 5000,  monthlyWithdrawals: "4 per month",    overdraftEligible: false },
     current:        { dailyLimit: 20000,  maxSingle: 10000, monthlyWithdrawals: "Unlimited",      overdraftEligible: true  },
     business:       { dailyLimit: 50000,  maxSingle: 20000, monthlyWithdrawals: "Unlimited",      overdraftEligible: true  },
     fixed_deposit:  { dailyLimit: null,   maxSingle: null,  monthlyWithdrawals: "At maturity only", overdraftEligible: false },
   };
   ```
3. `AccountLimits` type:
   ```ts
   interface AccountLimits {
     dailyLimit: number | null;
     maxSingle: number | null;
     monthlyWithdrawals: string;
     overdraftEligible: boolean;
   }
   ```
4. `getAccountLimits` returns `ACCOUNT_LIMITS[accountType.toLowerCase()] ?? null`
5. This file is the **single source of truth** for account type limits in the customer portal — no inline literals elsewhere

### FE-2: `AccountRulesCard` Component

1. New file: `src/features/accounts/components/AccountRulesCard.tsx`
2. Props: `accountType: string`, `overdraftLimit?: number`
3. Calls `getAccountLimits(accountType)` — returns null if unknown type; renders nothing if null
4. Displays a `Paper` card (consistent with BalanceCard styling) with title "Account Rules"
5. Rows:
   - Daily Transfer Limit: `formatCurrency(limits.dailyLimit)` or `"Not applicable"` if null
   - Max Single Transfer: `formatCurrency(limits.maxSingle)` or `"Not applicable"` if null
   - Monthly Withdrawals: `limits.monthlyWithdrawals` string
   - Overdraft: if `limits.overdraftEligible && overdraftLimit > 0` → `formatCurrency(overdraftLimit)`; if `limits.overdraftEligible && overdraftLimit === 0` → `"Not set"` ; if `!limits.overdraftEligible` → `"Not available"`
6. Uses the same MUI theme tokens as the rest of the customer portal — no hardcoded hex colours

### FE-3: `AccountDetailsPage.tsx` — Get Full Account Object

The page currently only fetches `balance` via `getAccountBalance`. To show account type and overdraft limit, the full `Account` object must be available:

1. `AccountDetailsPage` reads `account` from router state: `(location.state as { account?: Account } | null)?.account`
2. If not in state (direct URL access or page refresh): calls `useGetAccountsQuery()` and finds the matching account:
   ```ts
   const { data: accountsData } = useGetAccountsQuery(undefined, { skip: !!routerStateAccount });
   const account = routerStateAccount ?? accountsData?.data?.find(a => a.accountNumber === accountNumber);
   ```
3. `AccountRulesCard` renders below `BalanceCard` and above `TransactionsList`, receives `account.accountType` and `account.overdraftLimit`

### FE-4: Accounts List Page — Pass Route State

1. On the accounts list page (`AccountsPage` or wherever accounts are rendered), when navigating to `AccountDetailsPage`, pass the account object as route state:
   ```ts
   navigate(`/accounts/${account.accountNumber}`, { state: { account } });
   ```
2. This avoids an extra API call on first render for the common path (navigate from list → detail)
