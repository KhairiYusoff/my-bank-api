# US-10003 — Administrative Lifecycle Controls

**Phase:** 10
**Repos:** `my-bank-api`, `my-bank-admin-portal`
**Status:** 🏗️ In Progress
**Depends on:** Phase 9 complete ✅

---

## Value Statement

As a Banker, I want to manually suspend or reactivate accounts so that I can respond to fraud alerts, customer requests, or compliance requirements.

---

## Background

While dormancy is automated, we need manual overrides for various scenarios. Bankers must be able to suspend accounts for security or fraud reasons, and reactivate accounts once a customer has completed the necessary identity verification or addressed the fraud alert.

---

## Acceptance Criteria

### BE-1: Suspension Endpoint

- **Endpoint:** `PUT /api/accounts/:accountNumber/suspend`
- **Auth:** `banker` role only.
- Sets `Account.status` to `suspended`.
- Log `ACCOUNT_SUSPENDED` in `ActivityLog` with the staff's user ID.

### BE-2: Reactivation Endpoint

- **Endpoint:** `PUT /api/accounts/:accountNumber/reactivate`
- **Auth:** `banker` role only.
- Sets `Account.status` to `active`.
- Log `ACCOUNT_REACTIVATED` in `ActivityLog` with the staff's user ID.

### BE-3: Enforcement

- Update all transaction guards (withdraw/transfer/deposit) to block if status is `suspended` (same as `dormant`).

### FE-1: Banker Actions

- Add "Suspend Account" button to `AccountDetailPage` in the Admin Portal (visible to Bankers only).
- Add "Reactivate Account" button to `AccountDetailPage` (visible to Bankers only when status is `dormant` or `suspended`).
- Use `ConfirmationDialog` before applying status changes.

### FE-2: (Removed)

_The status audit trail requirement has been removed from this user story._
