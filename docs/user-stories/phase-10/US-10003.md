# US-10003 — Administrative Lifecycle Controls

**Phase:** 10
**Repos:** `my-bank-api`, `my-bank-admin-portal`
**Status:** 🏗️ In Progress
**Depends on:** Phase 9 complete ✅

---

## Value Statement

As an Admin or Banker, I want to manually suspend or reactivate accounts so that I can respond to fraud alerts, customer requests, or compliance requirements.

---

## Background

While dormancy is automated, we need manual overrides for various scenarios. Admins should be able to suspend accounts for security reasons, and Bankers should be able to reactivate accounts once a customer has completed necessary identity verification.

---

## Acceptance Criteria

### BE-1: Suspension Endpoint
- **Endpoint:** `PUT /api/accounts/:accountNumber/suspend`
- **Auth:** `banker` role only.
- Sets `Account.status` to `suspended`.
- Log `ACCOUNT_SUSPENDED` in `ActivityLog` with the staff's user ID.

### BE-2: Reactivation Endpoint
- **Endpoint:** `PUT /api/accounts/:accountNumber/reactivate`
- **Auth:** `banker` role only.
- Sets `Account.status` to `active`.
- Log `ACCOUNT_REACTIVATED` in `ActivityLog` with the staff's user ID.

### BE-3: Enforcement
- Update all transaction guards (withdraw/transfer/deposit) to block if status is `suspended` (same as `dormant`).

### FE-1: Admin Actions
- Add "Suspend Account" button to `AccountDetailPage` in the Admin Portal (visible to Admins).
- Add "Reactivate Account" button to `AccountDetailPage` (visible to Bankers/Admins when status is `dormant` or `suspended`).
- Use `ConfirmationDialog` before applying status changes.

### FE-2: Status Audit Trail
- Display a "Status History" section in the Admin Portal's `AccountDetailPage`.
- Fetch and show relevant `ActivityLog` entries filtered by account-related status changes.

---

## Technical Tasks

1. **Routes:** Add `/suspend` and `/reactivate` routes to `account.routes.js`.
2. **Service:** Implement `suspendAccount()` and `reactivateAccount()` in `account.service.js`.
3. **Admin UI:** Update `AccountDetailPage.tsx` and add necessary action components.
4. **Audit UI:** Create a `StatusHistory` component for the admin portal.
