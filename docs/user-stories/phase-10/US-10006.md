# US-10006 — Lifecycle Event Notifications

**Phase:** 10
**Repos:** `my-bank-api`, `notification-service`
**Status:** ⬜ Planned
**Depends on:** US-10001, US-10003, US-10004

---

## Value Statement

As a Customer, I want to receive immediate notifications (Email/In-app) when my account status changes (dormant, suspended, reactivated, or closed) so that I stay informed about the status of my funds and can take action if necessary.

---

## Background

Transparent communication is key to customer trust. Every major lifecycle event must trigger a notification to the customer's registered email.

---

## Acceptance Criteria

### BE-1: Dormancy Alerts
- **Pre-Dormancy:** Notify 30 days before 12-month inactivity mark. (Triggered by US-10001 cron).
- **Dormancy Activated:** Notify when status changes to `dormant`.

### BE-2: Administrative Alerts
- **Suspension:** Notify immediately when an Admin sets status to `suspended`. Include a message: "Your account has been suspended for security reasons. Please contact support."
- **Reactivation:** Notify when a Banker sets status back to `active`. Include a message: "Your account is now active and ready for use."

### BE-3: Closure Alerts
- **Request Received:** Notify when the customer submits a closure request.
- **Closure Finalized:** Notify when the Banker approves the closure. "Your account [Number] has been successfully closed."

### BE-4: Notification Service Integration
- Use `notification.service.js` in `my-bank-api` to dispatch these events.
- Ensure `notification-service` has templates for:
  - `ACCOUNT_DORMANT_WARNING`
  - `ACCOUNT_DORMANT_NOTICE`
  - `ACCOUNT_SUSPENDED`
  - `ACCOUNT_REACTIVATED`
  - `ACCOUNT_CLOSED`

---

## Technical Tasks

1. **Service Integration:** Add calls to `NotificationService.send()` in the respective status-change methods in `account.service.js`.
2. **Templates:** Create HTML templates for these events in the `notification-service` templates directory.
3. **Logging:** Ensure all sent notifications are logged in the `ActivityLog` for auditability.
