# US-5003 — Transaction Detail View (Admin Portal)

**Phase:** 5
**Repo:** `my-bank-admin-portal`
**Epic:** Transaction Enrichment
**Status:** ✅ Completed
**Depends on:** US-5001 ✅ complete

---

## Value Statement

As an admin or banker, I want to open any transaction and see the full unmasked detail — real name, full account number, device info, and processing time — so I can investigate disputes, verify identities, and spot anomalies without calling engineering.

## Acceptance Criteria

### 1. Transaction Table

1. Table adds a `Reference` column — shows `TXN-YYYYMMDD-XXXXX` or `—` for pre-Phase-5 rows
2. Each row has a `View` action button that opens the detail panel
3. Existing filter/sort/pagination behaviour unchanged

### 2. Detail Panel

1. Opens as a side panel or modal — does not navigate away from the table
2. All fields shown **unmasked**: full legal name, full account number
3. Direction badge: `TRANSFER SENT` / `TRANSFER RECEIVED` / `DEPOSIT` / `WITHDRAWAL`
4. `From` / `To` labels show the account owner's full name + account number
5. `Channel` displayed as a badge or plain text (e.g. `web`, `branch`, `system`)

### 3. Device Info Section

1. Shown only if `deviceInfo.ip` is populated (pre-Phase-5 records have none)
2. Displays `IP` and `User Agent` — User Agent truncated at 80 chars with `…`
3. If both fields are null: entire Device Info section hidden

### 4. Processing Time Section

1. Shown only if `processingTime.submittedAt` is populated
2. Displays `Submitted`, `Completed`, and computed `Duration` (difference in ms)
3. Duration formatted: under 1000ms → `468ms`, 1000ms+ → `1.2s`
4. If null: entire Processing Time section hidden

### 5. Null Field Handling

1. `reference` null → show `—` in table and detail
2. `counterpartName` null → show `—`
3. `counterpartAccount` null → omit account row
4. `balanceAfter` null → omit row
5. `fee` 0 or null → always show `RM0.00`
6. `memo` null → show `—`

### 6. Memo Input Field (Airdrop form)

1. The existing `Reference` field in the Airdrop form is misnamed — it is functionally a memo, not a reference (reference is system-generated)
2. Rename it to `Memo (Optional)`
3. Label: `Memo (Optional)`, placeholder: `Reason for airdrop (e.g. Q2 campaign)`
4. Max 255 characters
5. Changes required:
   - `AirdropFormData.reference` → `memo`
   - `airdropSchema.reference` → `memo` (make optional: `yup.string().max(255)`)
   - `AirdropRequest.description` → `memo`
   - `Airdrop.tsx` field name, label, placeholder, and `onSubmit` payload
