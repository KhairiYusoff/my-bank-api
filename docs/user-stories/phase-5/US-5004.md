# US-5004 — Currency Display Standardisation

**Phase:** 5
**Repo:** `my-bank-customer`, `my-bank-admin-portal`
**Epic:** Transaction Enrichment
**Status:** 🟡 Ready for Development
**Depends on:** —

---

## Value Statement

As a customer or admin, I want every monetary amount in the app to display consistently as `RM X,XXX.XX` — matching Maybank2u / CIMB Clicks standard — so the app looks like a real Malaysian banking product.

---

## Background

Two separate problems exist across the two client apps:

**`my-bank-customer`** — has a correct `formatCurrency()` util (`RM` + `en-MY` locale) but many components bypass it and use raw template literals like `${balance.toFixed(2)}`, producing `$500.00` instead of `RM 500.00`.

**`my-bank-admin-portal`** — `formatCurrency()` defaults to `currency: 'USD'`, causing `Intl.NumberFormat` to output `$` symbol. All admin portal monetary displays are wrong.

`MYR` is the ISO code — used in DB fields and API config only. `RM` is the display symbol — used in all UI.

## Acceptance Criteria

### 1. `my-bank-customer` — all amounts use `formatCurrency()`

1. Every monetary amount in the UI renders as `RM X,XXX.XX` (e.g. `RM 1,500.00`)
2. No raw `$` symbol appears anywhere in the app
3. All files in the Affected Files table above are updated to call `formatCurrency()` instead of template literals
4. `formatCurrency` in `src/utils/formatters.ts` is unchanged — it is already correct

### 2. `my-bank-admin-portal` — formatter default fixed

1. `formatCurrency` in `src/utils/formatters.ts` default changed from `'USD'` to `'MYR'`
2. All existing `formatCurrency(amount)` callsites (no second argument) now render `RM` automatically — no callsite changes needed
3. The `currency` parameter remains on the function signature for future FX use

### 3. Format standard

1. Symbol: `RM` followed by a space (e.g. `RM 500.00`)
2. Locale: `en-MY` — uses comma as thousands separator (e.g. `RM 1,500.00`)
3. Always 2 decimal places — `RM 500.00` not `RM 500`
4. Negative amounts: `-RM 500.00` (minus before RM, not `RM -500.00`)
