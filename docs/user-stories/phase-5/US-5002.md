# US-5002 — Transaction Receipt View (Customer Portal)

**Phase:** 5
**Repo:** `my-bank-customer`
**Epic:** Transaction Enrichment
**Status:** 🟡 Ready for Development
**Depends on:** US-5001 (API must be deployed first)

---

## Value Statement

As a customer, I want to tap on any transaction in my history and see a full receipt — with reference number, counterpart name, masked account, balance after, and fee — so I can verify details or quote a reference when raising a dispute.

## Acceptance Criteria

### 1. Transaction List Rows

1. Every transaction row is tappable — opens the receipt drawer
2. Transfer rows show counterpart name as a secondary muted line below the description (e.g. `Ahmad K****`)
3. Reference shown as a small muted line below the date (e.g. `TXN-20260529-00142`)
4. Rows without reference (pre-Phase-5 transactions) show no reference line — no placeholder

### 2. Receipt Drawer / Modal

1. Opens as a bottom drawer on mobile, side drawer or centred modal on desktop
2. Direction badge at top: `TRANSFER SENT` / `TRANSFER RECEIVED` / `DEPOSIT` / `WITHDRAWAL`
   - Determined by `type` + whether `account` is sender or receiver
3. Amount displayed prominently below the badge
4. Fields displayed in order: Reference → To/From → Account → Balance after → Date → Status → Fee → Memo
5. Label varies by direction: `To` for sent transfer, `From` for received transfer/deposit

### 3. Null Field Handling (Pre-Phase-5 Transactions)

1. `reference` is null → show `—`
2. `counterpartName` is null → show `—`
3. `counterpartAccount` is null → omit the account row entirely
4. `balanceAfter` is null → omit the row entirely (do not show `RM0.00`)
5. `fee` is null or 0 → show `RM0.00` (fee row always visible — builds trust)
6. `memo` is null → show `—`

### 4. Data Source

1. Drawer opens immediately with data already in the list response — no second API call on tap
2. If user navigates directly to a receipt (deep link future-proofing): call `GET /transactions/:id`
3. If the detail call fails: show `"Unable to load receipt. Please try again."` with a retry button

### 5. Close Behaviour

1. Drawer closes on: backdrop tap, swipe down (mobile), Escape key, close button
2. Closing does not reload the transaction list
